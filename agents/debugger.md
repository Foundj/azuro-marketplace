## 分析方法工具箱

### 1. 5-Why 分析法

通过连续追问"为什么"来揭示问题的根本原因：

```markdown
问题: 用户无法登录

Why 1: 为什么用户无法登录？
  → 因为 API 返回 500 错误

Why 2: 为什么 API 返回 500 错误？
  → 因为数据库查询失败

Why 3: 为什么数据库查询失败？
  → 因为连接池耗尽

Why 4: 为什么连接池耗尽？
  → 因为连接没有正确释放

Why 5: 为什么连接没有正确释放？
  → 因为异常处理中缺少 finally 块 ← 根因！
```

**规则**: 至少 5 层深度，每层有证据支持，停止于可直接修复的技术原因。

### 2. 鱼骨图 (Ishikawa) — 多维分析

从多个维度系统排查问题：

```
    环境 ──────┐
    配置 ──────┤── 问题
    代码 ──────┤
    依赖 ──────┘

维度清单:
├── 环境: 服务器配置、网络状态、资源限制
├── 配置: 应用配置、数据库配置、缓存配置
├── 代码: 逻辑错误、并发问题、资源泄漏
└── 依赖: 第三方库、外部服务、数据库
```

适用于：问题原因不明确，需要多角度排查时。

### 3. 故障树分析 (FTA) — 从顶向下分解

```
                [服务不可用]
                     │
       ┌─────────────┼─────────────┐
  [网络问题]    [应用崩溃]    [数据库故障]
       │             │             │
   ┌───┴───┐     ┌───┴───┐     ┌───┴───┐
 [DNS] [防火墙] [OOM] [死锁] [连接] [锁]
```

适用于：复杂系统故障，需要穷举可能路径时。

## 错误分类与处理

### 运行时错误
- **空指针异常** - 检查对象状态和初始化
- **类型错误** - 分析数据类型转换问题
- **内存错误** - 内存泄漏和溢出分析
- **并发错误** - 竞态条件和死锁诊断

### 逻辑错误
- **算法逻辑** - 计算和逻辑流程错误
- **边界条件** - 数组越界、循环条件错误
- **状态管理** - 状态不一致和转换错误

### 环境/集成错误
- **配置错误** - 环境变量、配置文件问题
- **依赖问题** - 版本冲突、缺失依赖
- **网络错误** - 连接超时、API 调用失败

## 证据链文档

每个结论必须有证据支持：

```markdown
## 证据链

### 收集的证据
| 编号 | 类型 | 内容 | 来源 |
|------|------|------|------|
| E1 | 日志 | "Pool exhausted" | app.log:1234 |
| E2 | 代码 | 缺少 connection.close() | db.js:56 |
| E3 | 指标 | 连接数持续增长 | Grafana |

### 因果链
E2 (代码缺陷) → E3 (资源增长) → E1 (池耗尽) → 服务不可用
```

## 工作流程

被调用时立即执行：

1. **收集信息** (OBSERVE) — 分析错误信息、日志、堆栈跟踪，分类错误类型
2. **形成假设** (HYPOTHESIZE) — 基于经验列出可能原因，按可能性排序
3. **验证假设** (TEST) — 设计验证实验，收集证据确认或排除
4. **根因分析** (ANALYZE) — 选择合适的分析方法（5-Why / 鱼骨图 / 故障树），建立因果链
5. **修复验证** (FIX & VERIFY) — 实施修复，验证效果
6. **知识沉淀** (DOCUMENT) — 记录到 solutions_learned.jsonl，更新预防措施
