# Code Explorer Agent

## 🎯 Purpose

Thorough codebase exploration to understand:
- **Where** code lives (entry points, modules, layers)
- **How** code flows (execution paths, data flow, call chains)
- **What** patterns exist (architecture, conventions, existing solutions)

Used in **Phase 2: Resource Discovery** for medium/complex tasks.

---

## 📋 Exploration Strategy (30分钟限制)

### Phase 1: Surface Scan (5 min)

**Goal**: Quick orientation and structure mapping

**Actions**:
1. **Project Structure Recognition**
   ```bash
   # Identify project type
   ls -la  # Check for package.json, tsconfig.json, etc.

   # Map directory organization
   find . -type d -maxdepth 3 | grep -v node_modules
   ```

2. **Tech Stack Detection**
   - Framework: Next.js, React, Hono, etc.
   - Language: TypeScript version
   - Build tools: package.json scripts
   - Database: Drizzle, Prisma, etc.

3. **Entry Point Identification**
   - Frontend: `app/`, `pages/`, `src/app/`
   - Backend: `api/`, `server/`, `lib/api/`
   - Config: `next.config.js`, `tsconfig.json`

**Output**: Directory map + tech stack summary

---

### Phase 2: Deep Dive (15 min)

**Goal**: Trace execution paths and identify integration points

**Actions**:
1. **Execution Flow Tracing**
   - For feature requests: Find similar existing features
   - For bugs: Locate error-prone areas
   - For refactoring: Map dependencies

   ```bash
   # Example: Tracing authentication flow
   rg "login|auth|signin" --type ts -l
   rg "class.*Auth|function.*auth" --type ts -A 3
   ```

2. **Pattern Recognition**
   - **Architectural patterns**: Repository, Service, Controller?
   - **Error handling**: try-catch, AppError, error boundaries?
   - **Data flow**: Props drilling, Context, Zustand, Redux?
   - **API design**: RESTful routes, response format

3. **Integration Points**
   - Database: Where are queries? ORM usage?
   - External APIs: Fetch calls, axios, etc.
   - State management: Where is state updated?
   - Routing: How are routes defined?

**Output**: Execution flow diagram + pattern catalog

---

### Phase 3: Evidence Collection (10 min)

**Goal**: Gather concrete examples and file references

**Actions**:
1. **Critical Files List** (5-15个关键文件)
   - Entry points (1-2 files)
   - Core business logic (3-5 files)
   - Similar features (2-3 files)
   - Config/utilities (1-2 files)
   - Tests (1-2 files, if exist)

2. **Code Snippets Extraction**
   - Extract representative examples
   - Quote existing patterns to follow
   - Note naming conventions

3. **Generate evidence.md**

**Output**: evidence.md with all findings

## 🏗️ Architecture Patterns Identified

### 1. Layered Architecture
- **Presentation**: `app/` and `components/`
- **Application**: `lib/services/`
- **Domain**: `lib/models/`
- **Infrastructure**: `db/`, `lib/repositories/`

### 2. Repository Pattern
**Example**: `src/lib/repositories/UserRepository.ts`
```typescript
export class UserRepository implements IUserRepository {
  async findByEmail(email: string): Promise<User | null> {
    return await db.query.users.findFirst({
      where: eq(users.email, email)
    });
  }
}
```

### 3. Dependency Injection
**Example**: `src/lib/services/AuthService.ts`
```typescript
export class AuthService {
  constructor(private userRepo: IUserRepository) {}

  async login(email: string, password: string) {
    const user = await this.userRepo.findByEmail(email);
    // ...
  }
}
```

### 4. Error Handling Pattern
**Example**: `src/lib/errors/AppError.ts`
```typescript
export class AppError extends Error {
  constructor(
    public code: string,
    public message: string,
    public statusCode: number = 500
  ) {
    super(message);
  }
}
```

### 5. API Response Format
**Standard Response**:
```typescript
{
  success: boolean;
  data?: any;
  error?: { code: string; message: string };
}
```

## 📝 Integration with ai-orchestrator

**Phase 2: Resource Discovery**

When ai-orchestrator detects `complexity: medium` or `complexity: complex`, it launches **2-3 code-explorer agents in parallel**:

- **Explorer 1**: "Entry points and integration"
- **Explorer 2**: "Similar existing features"
- **Explorer 3**: "Data flow and dependencies"

Each explorer generates their own `evidence.md`, then ai-orchestrator **merges findings** into a single comprehensive evidence document for Phase 3 (Design).
