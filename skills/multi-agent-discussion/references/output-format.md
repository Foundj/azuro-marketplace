# 输出格式规范

讨论汇总阶段生成的 `plan.md` 和 `task.md` 格式模板，基于 Fabula v5.x 规范。

## plan.md 模板

```markdown
---
name: <功能/项目名称>
overview: <一句话描述>
status: draft | approved
created: YYYY-MM-DD
participants:
  - role: "@PM"
    tool: "Codex"
  - role: "@Architect"
    tool: "Claude Code"
todos:
  - id: T1
    title: "<任务标题>"
    phase: 1
  - id: T2
    title: "<任务标题>"
    phase: 1
---

# <功能/项目名称>

## Context

### 问题根因
<从讨论中提取的核心问题描述>

### 信息来源
- 讨论记录: `docs/discussions/<topic>/discussion.md`
- 参与者: <角色列表及所用工具>
- 讨论轮次: <实际轮次数>

### 约束条件
<从讨论中识别的技术、业务、时间约束>

## 成功标准

硬验收条件（所有条件必须满足）：

1. <从 @QA 和 @PM 的讨论中提取的具体验收标准>
2. <可量化的指标>
3. <边界条件覆盖>

## 方案

### Phase 1: <阶段名称>

**目标：** <本阶段目标>

**改动清单：**
| 文件 | 操作 | 说明 |
|------|------|------|
| `path/to/file` | 新建/修改 | 具体改动内容 |

**验收标准：**
- [ ] <Phase 1 具体验收条件>

### Phase 2: <阶段名称>

（同上结构）

## 架构决策记录

从讨论中的 `> [!decision]` callout 提取：

### ADR-1: <决策标题>

- **背景：** <为什么需要做这个决策>
- **方案选项：**
  - A: <方案 A 描述>（<支持者>）
  - B: <方案 B 描述>（<支持者>）
- **决策：** <最终选择的方案>
- **理由：** <选择原因，引用讨论中的论据>
- **后果：** <预期影响>

### ADR-2: <决策标题>

（同上结构）

## 信心度分析

| 维度 | 信心度 | 说明 |
|------|--------|------|
| 需求明确性 | 高/中/低 | <基于讨论共识程度> |
| 技术可行性 | 高/中/低 | <基于 @Architect 评估> |
| 工作量估计 | 高/中/低 | <基于讨论分歧程度> |
| 风险可控性 | 高/中/低 | <基于 @Security/@QA 评估> |

## 开放问题

从讨论中未达成共识的 `#pending` 和 `#needs-input` 项提取：

- [ ] <待解决问题 1>
- [ ] <待解决问题 2>
```

## task.md 模板

```markdown
# <功能/项目名称> — 任务清单

> 状态: 未开始 | 进行中 | 已完成
> 更新: YYYY-MM-DD
> 来源: `docs/discussions/<topic>/plan.md`

## 执行规则

1. 按 Phase 顺序执行，每个 Phase 内任务可并行
2. 每个 Phase 完成后执行 Review Gate
3. 勾选任务时附注完成时间
4. 遇到阻塞在任务后标注 `[BLOCKED: 原因]`

---

## Phase 1: <阶段名称>

- [ ] **T1** <任务标题>
  - 描述: <具体要做什么>
  - 文件: `path/to/file`
  - 验收: <完成标准>

- [ ] **T2** <任务标题>
  - 描述: <具体要做什么>
  - 文件: `path/to/file`
  - 验收: <完成标准>

### Review Gate 1

- [ ] Code Review: <检查要点>
- [ ] 测试命令: `<具体测试命令>`
- [ ] 结论: _（待填写）_

---

## Phase 2: <阶段名称>

- [ ] **T3** <任务标题>
  - 描述: <具体要做什么>
  - 文件: `path/to/file`
  - 验收: <完成标准>

### Review Gate 2

- [ ] Code Review: <检查要点>
- [ ] 测试命令: `<具体测试命令>`

## 变更记录

| 日期 | 变更 | 原因 |
|------|------|------|
| YYYY-MM-DD | 初始创建 | 基于讨论汇总生成 |
```

## 生成规则

汇总时遵循以下规则：

1. **决策提取**：扫描所有 `> [!decision]` callout 和 `#consensus` 标签
2. **冲突标注**：`#pending` 项在 plan.md 的"开放问题"中列出
3. **来源追溯**：每个 ADR 注明支持该决策的讨论轮次和角色
4. **任务拆解**：每个 Phase 的任务从 plan.md 的改动清单推导
5. **验收继承**：task.md 的验收标准从 plan.md 的成功标准和 Phase 验收标准继承
